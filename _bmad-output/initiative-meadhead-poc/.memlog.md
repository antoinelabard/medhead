- (requirement) R1 (exigences §Scénario, §Exigences) Pour une spécialité et une localisation d'urgence, l'API REST renvoie l'hôpital le plus proche disposant d'au moins un lit disponible et offrant la spécialité ; le scénario Fred Brooks / Julia Crusher / Beverly Bashir propose Fred Brooks.
- (requirement) R2 (exigences §Scénario) Quand un hôpital est recommandé, un événement de réservation de lit est publié et observable par un consommateur.
- (requirement) R3 (mission §Back-end, Points de vigilance) La proximité se mesure en distance réellement à parcourir, pas à vol d'oiseau ; un cas où le plus proche à vol d'oiseau n'est pas le plus proche par la route le démontre.
- (requirement) R4 (données NHS) Les spécialités sélectionnables sont celles des Données de référence NHS (groupe et spécialité) ; une spécialité hors liste est refusée avec une erreur explicite.
- (requirement) R5 (exigences §Exigences interface) Une page web unique permet de choisir une spécialité, de saisir la localisation et d'afficher l'hôpital recommandé renvoyé par l'API.
- (requirement) R6 (exigences §Exigences protection ; DDA §Contraintes) Les données du patient transmises sont protégées en transit et seuls des appelants authentifiés obtiennent une recommandation ; un appel non authentifié est refusé.
- (requirement) R7 (exigences §Exigences tests ; principes B4, C4-V) La PoC est validée par une pyramide de tests unitaires, d'intégration et E2E, les critères d'acceptation métier écrits en scénarios BDD dans le langage du domaine.
- (requirement) R8 (exigences §Déclaration, §Exigences tests) Un test de stress montre un temps de réponse inférieur à 200 ms jusqu'à 800 requêtes par seconde par instance de service, avec un rapport de mesures.
- (requirement) R9 (exigences §Exigences CI/CD ; principes B3, C4-VI ; mission §CI/CD) Un pipeline CI/CD se déclenche sur les push et PR, découpé en étapes distinctes (tests, build, images), et conserve des rapports d'exécution des tests inspectables.
- (requirement) R10 (exigences §Exigences readme ; mission §CI/CD) Un readme.md explique comment builder et exécuter la PoC, exécuter les tests, le fonctionnement du pipeline et le workflow Git de façon réutilisable par les équipes.
- (requirement) R11 (exigences §Exigences reporting ; mission §Reporting) Un document de reporting justifie les technologies, le respect des normes (RGPD) et des principes, présente résultats, métriques de temps d'exécution de l'API et enseignements.
- (requirement) R12 (exigences §Exigences bloc de construction ; déclaration §Continuum) La PoC sert de bloc de construction ou de modèle : contrat d'API publié en OpenAPI, code partageable, stratégie de test et pipeline réutilisables.
- (requirement) R13 (déclaration §Contenu de l'architecture ; principes B1) Quand un service auxiliaire factice est indisponible, l'API répond dans le délai avec une erreur explicite ou un résultat dégradé, démontré par un test avec le service coupé.
- (constraint) Backend en Java, API RESTful capable de s'inscrire dans une architecture microservice (exigences §Exigences ; décision utilisateur).
- (constraint) Frontend Angular, parmi les frameworks imposés Angular/React/VueJS (exigences §Exigences ; décision utilisateur).
- (constraint) Déploiement par conteneurs Docker, infrastructure immuable et reproductible (principes C3 ; décision utilisateur).
- (constraint) Code, issues, PR et CI sur GitHub ; workflow Gitflow documenté (exigences §Exigences ; décision utilisateur).
- (constraint) Données factices ou anonymisées uniquement, PoC isolée de toute production (principes C4-II ; DDA §Limites).
- (constraint) Les principes B1 à B4 ne sont pas assouplis pour la PoC (principes C4-IV).
- (constraint) Les composants publient leurs événements métier (principes B6).
- (constraint) Contrat de service spécifié en OpenAPI ; Javadoc pour le code, Markdown pour la documentation projet (principes C3).
- (constraint) Données patient traitées conformément au RGPD (DDA §Contraintes ; principes A3).
- (constraint) Les services auxiliaires peuvent être factices avec des contrats simplifiés, lacunes documentées (déclaration §Simplifications ; mission §Back-end).
- (constraint) Le pipeline ne déploie pas la PoC en production sur un cloud (mission §CI/CD).
- (assumption) Backend Spring Boot, recommandé par la mission §Back-end.
- (assumption) Jeu de données d'hôpitaux fictifs situés au Royaume-Uni, incluant les trois hôpitaux du scénario.
- (assumption) Les objectifs métier (plus de 90 % d'acheminements corrects, 18,25 vers 12 min) ne sont pas mesurables par la PoC ; elle démontre le comportement qui y contribue et le reporting en discute.
- (assumption) Tests de stress avec JMeter (mission §Back-end) contre l'image Docker, rapport versionné.
- (assumption) La présentation au comité d'architecture est hors backlog.
